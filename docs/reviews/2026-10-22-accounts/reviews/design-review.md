## Summary
Not ready to ship as is. The sign-in, account sheet, conflict dialog and teacher gate are visually consistent with the product. The motion lens found nothing: dialogs use the existing 200 ms ease-out tokens, status changes are not animated, and reduced motion is covered. Two things matter most:
- The footer says "progress saved online" while the header says Offline. A student can be misled about whether their work is safe.
- The sign-in error sits under the primary button, where the iPhone keyboard probably covers it. This is by reasoning only; I could not reproduce it.

There are also three measured defects: truncated status text at 375 px and below, a broken Name header in the teacher grid after horizontal scroll, and teacher selects that render 23 px tall in WebKit.

## Checked and fine
- **A02 sign-in sheet:** focus ring is visible, the input is 17 px so iOS will not zoom, placeholder contrast is OK, autocapitalize and spellcheck attributes are right, and the privacy text is unchanged.
- **A03 error colour:** `#a15c00` on its tinted background is about 4.55:1 in light mode (just passes). Dark mode is fine.
- **A07 conflict dialog:** the two copies stack at 390 and sit side by side at 1280. There is one primary button, and the wording is plain student language.
- **A08 teacher form:** label and error copy are fine. The page has one h1 and `noindex`.
- **A09 grid:** colour is never the only signal because the percentage is shown. Cell text contrast is high, and the grid region has a label and `tabindex`. The unscrolled grid looks right at 1280.
- **A10 help section:** content and structure are fine.
- **Standard states 14 and 15:** Move progress and What's new are fine apart from finding 7.
- **Motion:** dialog entry uses the 200 ms `--ease-out` token, and reduced motion is handled. Header buttons are 44 px tall at 390, 360 and 320. No horizontal page scroll at any width tested.

## Design rules
- §5.7 says the brand name hides only when signed in. The CSS hides it for everyone at ≤ 430 px (finding 6).
- §5.1 says danger buttons appear only in confirm dialogs. The sign-out button is an exception that is not written down (finding 8).
- §5.7 says the status is text that must be readable, but nothing says how it must behave when narrow (wrap vs truncate). Add "wraps, never truncates" (finding 3).
- §8 requires 44 px targets, but native selects are not covered. Add a note on selects and `appearance` (finding 5).
- §5.8 needs a note on name-column width on phones and on header z-order (findings 4 and 9).
- §1, §5.7 and §9 do not cover signed-in versions of the welcome and Move progress copy (finding 7).
- §5.7 does not list the footer note as a state that must follow the sync status (finding 1).
